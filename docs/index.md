# :statue_of_liberty: Lakehouse Freedom

**Build managed. Stay open. Keep your freedom.**

Databricks provides a powerful managed lakehouse platform built around open technologies such as Apache Spark and Delta Lake. But how portable is a real Databricks solution?

Lakehouse Freedom is an executable reference architecture. It shows how to design Databricks workloads with portability in mind, and runs the same workload on a fully open-source lakehouse built on [OpenLakehouse.io](https://openlakehouse.io). It doesn't argue about vendor lock-in in the abstract: it runs the workload and measures how much freedom you keep.

## The question

> If we build a modern data platform on Databricks today, how much freedom do we retain to run the same data, transformations and workloads using only open-source technologies tomorrow?

## The message

The project is about architectural optionality. It is not an argument against Databricks. A managed platform is a reasonable choice, and the [Freedom Principles](freedom-principles.md) say explicitly that managed services are allowed to be better (F6). The aim is to keep ownership of your data, your business logic and your future architectural choices while you use one.

## Where to start

- **Run it.** [Get started](getting-started.md) brings up the OpenLakehouse side on a laptop with three `make` commands.
- **Read the results.** The [latest Freedom Report](report.md) is generated by the tooling and committed with the measurements behind it.
- **Apply it.** The [Freedom Architecture](freedom-architecture.md) and [Freedom Path](freedom-path.md) describe how to structure your own workload and what a migration involves.
