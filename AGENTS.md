# Repository workflow

- Submit every change through a pull request.
- Never merge a feature branch directly into `main`, locally or remotely.
- Commit changes on a feature branch, push that branch, and open a pull request for review.
- Do not keep redirects, compatibility stubs, legacy aliases, or "this page moved" placeholders when removing or renaming docs or code. Remove the obsolete artifact unless backward compatibility is explicitly requested.
- Describe the repository by its current purpose. Do not preserve an earlier purpose through negative positioning such as "this is not a migration tool" or explanations of what the project used to be. Keep only limitations that are necessary to interpret current results accurately.
